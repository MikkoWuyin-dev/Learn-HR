# Handoff brief — for the agent receiving this bundle

You are looking at a design system **reverse-engineered from a live site** (https://wakeout.app,
captured 2026-10-20). It is exact, not interpretive. Read this before touching anything.

## 0. Sanity-check the bundle first

```bash
sha256sum -c SHA256SUMS.txt
```

Generation is deterministic by design (no timestamps in `artifacts/manifest.json` or
`ref/contrast.json`), so this passes both before you start and after a full rebuild —
`npm run check` must leave every checksum `OK`. If a hash differs, a file was edited outside
the pipeline (or the tokens-only bundle was regenerated by hand). The tokens-only bundle has no
`package.json` on purpose: `node tools/build-tokens.mjs` needs zero dependencies.

Fastest orientation, in order: `artifacts/standalone.html` (renders the whole system offline, one file,
fonts inlined) → `docs/DESIGN.md` (the spec) → `tokens/tokens.json` (the values + their evidence).

## 1. The one rule of this repo

`tokens/tokens.json` is the **source of truth**. `artifacts/*`, the docs site, and `standalone.html` are
**all generated**. Never hand-edit a file in `artifacts/` — edit the JSON and run `npm run tokens`. If
you edit `artifacts/wakeout.css` by hand, the next build silently erases it.

Every token carries `evidence` (the CSS declaration or utility class it was read from) and often
`usage` (how many times that class appeared in the sampled HTML). If you "improve" a value, you are
no longer shipping an extraction — you are shipping an opinion. That is allowed, but say so: set
`"inferred": true` and put the reasoning in `note`.

## 3. Invariants (violating these breaks the system, not just a component)

1. **`--wk-ink` (#043629) is the text colour, every border colour, and every shadow colour.**
   Introducing a second dark for outlines is the single most common way to break this system.
2. **Elevation = 0-blur solid offset, x === y.** `3px/6px/10px 6px spread 0`. No blurred or
   alpha shadows — they do not exist in the source and will read as a different brand.
3. **Radius is not Tailwind's.** The site remaps from `--radius: 1.25rem`, so `rounded-2xl` is
   **2.25rem** and `rounded-3xl` is **3rem**. Never "fix" these back to 1rem/1.5rem.
4. **`font-display` carries weight and tracking.** It is `Fredoka + font-weight:700 +
   letter-spacing:-.02em` as one unit (mirrored in the generated `@utility font-display`). Headings
   must not add `font-bold` — it is already implied.
5. **Saturated fills get ink text, never white.** `--wk-primary-foreground` is ink. Only
   `ink`/`stage`/`dusk` surfaces take paper-coloured text.
6. **Interaction animates `transform` + `box-shadow` only, 150ms `cubic-bezier(0,0,.2,1)`.**
   Press offset (4px) equals `shadow-sticker-sm` (3px + 1px border) so the element lands flush —
   changing one without the other destroys the physicality.
7. **Long loops (0.9–12s) are for decorative, `aria-hidden` art only.** Never animate content.
8. **Tilt has a ceiling:** `-1deg` interactive · `-2deg` stickers · `-6…12deg` callouts · never on
   paragraphs, form labels, or anything read for more than a second.
9. **Uppercase always comes with `tracking-widest` (.1em).** An uppercase label at normal tracking
   is a bug here.
10. **Uppercase micro text starts at 10px; 9px exists only inside mock app chrome.**

## 4. Known traps I already hit (so you don't)

- **`tailwind-merge` corrupts this system.** Its font sizes are named `text-body-sm`, `text-eyebrow`
  etc., which tailwind-merge classifies as *text colours* and uses to drop real colour utilities
  like `text-paper` from the same element. `src/ui.tsx` uses plain `clsx` on purpose. Resolve
  conflicts structurally (see the `ghost` variant, which omits `border-3 shadow-sticker` entirely)
  or with the `!` important prefix.
- **`hidden` can lose to a component's own `inline-flex`.** Utility order is alphabetical, not
  intent-driven: `.inline-flex` is emitted after `.hidden`, so `hidden md:inline-flex` on a component
  that already sets `inline-flex` does nothing. Use `max-<bp>:hidden` instead.
- **Never put deliverables in a directory named `dist` or `build`.** In this kind of sandbox those
  names are excluded from the persisted workspace snapshot (as are `out/`, `target/`, `coverage/`,
  `node_modules/` and dotfile caches), so files written there exist in the shell but disappear from
  the user's file viewer and from later turns. The original version of this repo emitted its tokens
  to `dist/`, and the user was handed "File not found in workspace" for a file that built fine.
  Generated output now lives in `artifacts/`. Since Vite's default `outDir` *is* `dist/`, this repo
  sets `build.outDir: "build"` — so the site build can never overwrite the tokens, and only the
  regenerable site bundle sits in an ignored name. If you "clean up" that config, the next
  `vite build` deletes `artifacts/` mid-build.
- **Tailwind content scanning must be restricted** (`source(none)` + `@source "../src/**/*.{ts,tsx}"`
  in `src/styles.css`). Otherwise it scrapes `ref/*.html` — the reference site's own markup, full of
  arbitrary values — and generates ~40 kB of junk utilities.
- **Two tokens are interpolated, not measured** (`dimension.radius.md`, `motion.duration.instant`),
  because the reference never shipped a rule for them. Don't build on them.

## 5. Re-extracting from another site

```bash
curl -s <site>/_next/static/chunks/<hash>.css -o ref/main.css
curl -s <site> -o ref/page-home.html          # a handful of rendered pages
npm run extract                                # → ref/evidence.json + ref/REPORT.md
# rewrite tokens/tokens.json from that report, then:
npm run tokens && npm run contrast && npm run check && npm run standalone
```

The extractor only parses CSS/HTML — no browser is driven, so layout, wrapping, container queries
and locale variants are out of scope by design.

## 6. Verify before you hand anything back

```bash
npm ci
npm run check        # tsc --noEmit + vite build; `npm run tokens` runs first
```

Then assert the tokens landed in real CSS, not just in the JSON:

```bash
grep -o '\.rounded-2xl{[^}]*}' build/assets/*.css   # → border-radius:var(--wk-radius-2xl)
grep -o '\.shadow-sticker{[^}]*}' build/assets/*.css # → --tw-shadow:var(--wk-shadow-sticker)
```

The strongest check is computed styles in a browser: a button must report `border-top-width: 3px`,
`border-top-color: rgb(4, 54, 41)`, `box-shadow: rgb(4,54,41) 6px 6px 0px 0px`,
`border-radius: 36px`, `transition-duration: 0.15s`, `transition-property: transform, box-shadow`.
An `h1` must report `font-family: Fredoka…`, `font-weight: 700`, `letter-spacing` ≈ `-0.02em`.

A build that passes proves nothing about whether a class maps to a token — grep the emitted CSS.

## 7. Open work, ranked

1. **Contrast debt.** 11 of 17 approved pairs pass AA (4.5:1). Four are 3–4.5:1 and are legal only
   at 18px+ bold (`red`/`lime-deep` on paper, `ink/60`); `ember` on paper **fails** (2.67:1). The
   extraction kept the reference's behaviour — fixing it is a design decision, so it is documented,
   not silently patched. See `ref/contrast.json`.
2. **No dark theme.** The reference ships one theme. The alias layer is built for it (see the docs'
   Theme Lab), but `stage`/`dusk` are showcase surfaces, not a product dark mode: `--wk-border`,
   focus ring and `muted` have no night values yet.
3. **`src/ui.tsx` is a reference implementation, not a finished library** — no tests, no a11y
   regression suite, no focus-trap/menu-primitives, no build output for consumers (`exports`,
   types, CSS subpath). If the job is "make this shippable", start there.
4. **In-product screens are reconstructed.** `/try/*` is disallowed by robots.txt, so window chrome,
   toggles and stat tiles come from the marketing mocks, not the real app.
5. **Form controls barely exist in the source** — inputs/selects/errors are under-specified; only a
   toggle and one dark-panel control recipe were measurable.
